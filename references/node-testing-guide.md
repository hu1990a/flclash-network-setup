# 节点稳定性与安全性批测指南

本步骤放在 CLI 时区配置之前。目标是先从用户允许的国家或地区中找出稳定、出口信誉较好的候选，让用户确认最终节点，再用实测位置设置 CLI 时区。

## 1. 批测前确认

1. FlClash 已加载经过验证的订阅，混合端口正在监听。
2. 外部控制器只监听 `127.0.0.1:9090`。如果未开启，让用户在界面中开启；不直接改写未知状态文件。
3. 记录当前订阅、策略组和节点。多个订阅一次只测试一个，切换订阅时以界面显示为准。
4. 从 `/proxies` 读取核心候选，与订阅和界面显示名逐字匹配。数量或名称无法对应时停止，不按位置猜测。
5. 先确认用户允许测试的地区。节点名只有国家、没有城市时，按“国家但没有城市”说明，实际城市以检测结果为准。

## 2. 两阶段测试

先对所有候选执行本地稳定性测试，不发送公网 IP：

```powershell
python scripts/probe-nodes.py `
  --group "<主策略组界面名称>" `
  --candidate "<候选1界面名称>" `
  --candidate "<候选2界面名称>" `
  --rounds 3 `
  --latency-only
```

每个候选至少 3 轮。脚本记录成功轮数、中位延迟和最大值减最小值形成的抖动。优先保留全轮成功的候选；任何 `TIMEOUT` 都显示，不用单次最低延迟掩盖失败。

安全检测前，一次性告诉用户候选数量，以及 `ipcheck` 会把每个出口 IP 发给 `ip-api.com`、`proxycheck.io` 和 `stopforumspam.org`。明确获得这次批测授权后运行：

```powershell
python scripts/probe-nodes.py `
  --group "<主策略组界面名称>" `
  --candidate "<稳定候选1界面名称>" `
  --candidate "<稳定候选2界面名称>" `
  --rounds 3 `
  --confirm-external-ip-services
```

没有 `--confirm-external-ip-services` 时，脚本拒绝运行安全检测。脚本只接受本机 `127.0.0.1:9090` 控制器，捕获 ipcheck 输出后只保留城市、运营商、时区、机房属性、风险分和滥用记录，不保留真实公网 IP。

## 3. 推荐规则

结果按以下顺序比较：

1. 全部延迟轮次成功；稳定性优先于一次更快。
2. 安全查询完整，且没有 `Compromised Server`。
3. 风险分更低。
4. Stop Forum Spam 未收录；已收录时比较次数和最近时间。
5. 实际地区符合用户允许范围，并能与目标 CLI 时区匹配。
6. 中位延迟更低、抖动更小。

不要把这些指标合成无法解释的自创总分。报告最多给三个选择：

- 最稳妥：稳定且出口信誉最好。
- 延迟优先：同一安全等级中延迟更低。
- 地区优先：用户明确需要的国家或城市中表现最好。

不同节点名可能共用同一个实际出口。城市、运营商、风险和滥用结果完全相同时，提示用户“可能共用出口”，不要把名称差异当成安全差异。

## 4. 应用与回滚

`probe-nodes.py` 无论成功或失败都恢复测试前节点，输出中的 `applied` 固定为 `false`。向用户展示推荐后，由用户选择；只有用户明确允许自动应用最佳项时才能代选。

应用最终节点后重新运行一次 ipcheck。确认实际位置、风险、滥用记录和延迟符合推荐结果，再关闭外部控制器并验证 `127.0.0.1:9090` 不再监听。恢复失败、控制器暴露到局域网、界面名与核心名不一致时立即停止。

## 5. 最后设置 CLI 时区

用最终节点的实测 IANA 时区给用户两个选择：

1. 固定比北京时间慢 12 小时：`America/Puerto_Rico`，方便肉眼换算，但可能与出口不一致。
2. 与最终出口一致（推荐）：例如加州使用 `America/Los_Angeles`，降低位置与时区冲突并自动跟随夏令时。

用户选择后再写入 `TZ`，随后重新打开终端并完成统一验收。系统时区默认保持不变。
